# Komus Data — исследование моделей кредитного скоринга

Проект исследования моделей машинного обучения для прогнозирования дефолта контрагента на горизонте 1 года.

В проекте реализованы подготовка данных, формирование наборов признаков, запуск экспериментов с несколькими моделями и демонстрационный интерфейс на Streamlit.

## Что находится в проекте

Основные направления:

- подготовка рабочего датасета из исходных данных;
- исследование и отбор признаков;
- сравнение моделей;
- запуск эксперимента на выбранном наборе признаков;
- расчёт AUC, GINI, Recall и F1;
- сохранение истории экспериментов;
- демонстрационный интерфейс для пользователей без необходимости работать непосредственно с кодом.

## Модели

В текущей версии доступны:

- Logistic Regression
- LightGBM
- CatBoost
- XGBoost
- Random Forest

Архитектура backend позволяет добавлять новые модели через модуль `src/models.py`.

Для моделей используются разные правила обработки пропусков:

| Модель | Обработка NaN |
|---|---|
| LightGBM | пропуски оставляются |
| CatBoost | пропуски оставляются |
| Logistic Regression | заполнение медианой |
| XGBoost | пропуски оставляются |
| Random Forest | заполнение медианой |

## Наборы признаков

В текущей версии используются два основных набора.

### BASE COMPACT

38 исходных признаков датасета заказчика.

### BASE + SPARK

47 признаков:

- 38 исходных признаков;
- 9 дополнительных динамических признаков, рассчитанных на основе данных SPARK.

Кроме готовых наборов признаков backend поддерживает запуск эксперимента с произвольным выбранным подмножеством доступных признаков.

## Целевая переменная

`DefMark` — признак дефолта.

## Подготовка данных

Исходный датасет заказчика не хранится в GitHub.

Для воспроизводимости предусмотрен скрипт:

```text
src/prepare_dataset.py
Он формирует рабочий файл:

data/base/komus_base38.parquet

Полученная база содержит:

362 018 объектов;
38 признаков;
целевую переменную DefMark;
всего 39 столбцов.

Запуск подготовки:

python src/prepare_dataset.py
TRAIN / TEST

Для экспериментов используются фиксированные индексы:

experiments/train_indices.csv
experiments/test_indices.csv

Это позволяет использовать одинаковое разделение данных при сравнении разных моделей и наборов признаков.

Метрики

Для оценки моделей рассчитываются:

AUC — площадь под ROC-кривой;

GINI — коэффициент, связанный с AUC:

GINI = 2 × AUC − 1

Recall — полнота обнаружения дефолтов;
F1 — гармоническое среднее Precision и Recall.

Демонстрационное приложение

Интерфейс реализован на Streamlit.

Запуск:

streamlit run app/app.py

В интерфейсе пользователь может:

выбрать модель;
выбрать набор признаков;
выбрать отдельные признаки;
запустить эксперимент;
увидеть рассчитанные метрики;
просмотреть историю экспериментов;
ознакомиться с каталогом признаков.
